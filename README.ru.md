# ap_portal для ESPHome

[English](README.md) · [Українська](README.uk.md) · **Русский**

> **Статус: 0.x.** Точка доступа, щадящий режим, стартовая страница, поиск сетей и пароль
> работают, проверены на ESP32-S3 и стоят на двух реальных устройствах: датчик движения Move Sensor BLE
> (ESP32-C3, esp-idf) и монитор батареи Deye (ESP32-C3, Arduino); следующие — весы HiveScale.
> Закрепляйте тег релиза (`@v0.2.0`) или коммит, если от устройства что-то зависит.

ESP32 держит **свою точку доступа Wi-Fi одновременно с подключением к роутеру**. Телефон,
подключившийся к ней, получает окно **«Войти в сеть»** и попадает на страницу устройства — есть
роутер или нет.

Чего не умеет штатный `captive_portal` ESPHome, а умеет `ap_portal`:

- точка доступа остаётся включённой после подключения к роутеру;
- своя стартовая страница: проверка связи телефона перенаправляется на неё, свои страницы устройства
  открываются напрямую;
- запросы из домашней сети не трогаются — стартовую страницу видят только клиенты точки доступа;
- **щадящий режим**: без роутера ESPHome сканирует все каналы и перезапускает адаптер, телефоны на
  точке теряют пакеты или отваливаются (замер: 45 % потерь). `ap_portal` держит радио на канале
  точки (замер: меньше 2 % потерь вместе с возвратом роутера) и всё равно находит роутер, когда тот
  появится, даже на другом канале;
- к SSID можно добавить хвост MAC, пароль меняется с самого устройства и переживает перезагрузку.

Работает на любом ESP32 с фреймворком ESP-IDF или Arduino (проверено на ESP32-C3 и ESP32-S3; Arduino — на ESP32-S3).
Проверено с **ESPHome 2026.11.x**; на других версиях сборка выдаёт предупреждение.

## Быстрый старт

```yaml
wifi:
  ssid: my-router
  password: router-password
  ap:
    ssid: My-Device
    password: device1234
    manual_ip:                  # 100.64.4.1: Android показывает окно входа (на частный адрес — нет)
      static_ip: 100.64.4.1
      gateway: 100.64.4.1
      subnet: 255.255.255.0

web_server:
  version: 3
  local: true                   # страница работает без интернета

external_components:
  - source: github://daimonkor/esphome-ap-portal@v0.2.0
    components: [ap_portal]

ap_portal:
```

SSID, пароль и адрес берутся из `wifi: ap:` и в `ap_portal` не дублируются.

## Настройка

```yaml
ap_portal:
  id: portal
  active: true                  # true / false / !lambda — когда работают точка, DNS и страница
  ssid_suffix_mac: false        # MyDevice -> MyDevice-4FD30C
  password_persist: false       # хранить пароль из ap_portal.set_password после перезагрузки
  log_exclude_prefixes: []      # пути, которые не пишутся в лог VERBOSE, например [/sd/]
  dns:
    enabled: true
  landing:
    mode: redirect              # единственный режим с 0.2.0 (page и gate удалены)
    path: /welcome
    # переменные встроенной страницы (доступны и в своём html):
    title: My Device            # по умолчанию friendly_name
    accent_color: "#3d7bff"     # текст на кнопке белый или чёрный — по контрасту
    icon_svg: {file: icon.svg}  # или строкой "<svg ...>"
    primary_label: Open device page
    secondary: {label: Router Wi-Fi, href: "/#wifi"}
    # своя страница вместо встроенной (шаблон, см. ниже):
    # html: {file: landing.html}
    # vars:                     # свои переменные шаблона
    #   battery: !lambda return to_string((int) id(soc).state);
    #   fw: "1.2.3"
  api:                          # адреса /ap_portal/ и client.js для своего сайта
    enabled: true
    from_home: false            # и из домашней сети (под логином web_server)
  router_fallback:              # сеть со страницы не подключается после перезагрузки:
    timeout: 45s                # ждать столько, затем по очереди шаги ниже
    previous: true              # вернуться к сети, на которой устройство было до этого
    firmware: true              # затем к сети из YAML (wifi: ssid / networks)
    # firmware: {ssid: Backup-Net, password: !secret backup}   # или своя запасная сеть
  on_router_fallback:           # to: "previous" / "firmware" / "none", ssid
  wifi_page:                    # встроенная страница /wifi, только для клиентов точки
    enabled: true               # список сетей, подключение к роутеру, пароль точки доступа
    path: /wifi                 # сюда ведёт вторая кнопка стартовой страницы, если не задан `secondary`
    ap_password: true           # блок пароля точки доступа
    # later_button: false       # «Сохранить, подключить позже»; по умолчанию выключена при wifi: ap: ap_mode: always_on или keep_ap_on_connect
  password_reset:               # с password_persist: вернуть пароль из wifi: ap:
    power_cycles: 4             # кнопка RESET (или питание) 4 раза подряд, каждый запуск короче 10 с; 0 = выкл
    # pin: GPIO2                # кнопка, которую держат во время работы; по умолчанию BOOT на плате
    hold: 5s                    # (GPIO0 на ESP32/S2/S3, GPIO9 на C3/C6, GPIO28 на C5); pin: false = выкл
                                # своя кнопка на GND: pin: {number: GPIO2, mode: {input: true, pullup: true}, inverted: true}
  on_client_connected:          # mac (std::string)
  on_client_disconnected:       # mac
  on_ap_restored:               # ESPHome выключил точку, ap_portal поднял её снова
  on_portal_start:
  on_portal_stop:
  on_landing:                   # ip, path — показана стартовая страница
  on_power_cycle:               # count — быстрый запуск в серии (мигнуть светодиодом)
  on_password_reset:            # source: "power_cycles" или "button"
```

Действия: `ap_portal.scan` (фоновый поиск сетей без разрыва связи с роутером),
`ap_portal.set_password` (`password:` пустой — открытая сеть, или 8..63 символа; применяется через
2 с, чтобы страница, которая попросила, успела получить ответ; с `password_persist: true`
переживает перезагрузку), `ap_portal.reset_password` (вернуть пароль из `wifi: ap:`, сохранённый
стирается).

Из лямбд: `id(portal).is_active()`, `client_count()`, `ap_ip()`, `ssid()`, `is_scanning()`,
`has_custom_password()`.

### Страница Wi-Fi

`/wifi` показывает сети вокруг (фоновый поиск, пока роутер подключён), подключает устройство к
сети роутера (сохраняет ESPHome, переживает перезагрузку) и меняет пароль точки доступа. Её видят
только клиенты точки доступа — никогда домашняя сеть; защита — пароль
точки. Кнопка Wi-Fi на стартовой странице открывает её попапом на месте.
Её адреса — под `/ap_portal/`. Если у устройства своя страница настроек Wi-Fi, отключите:
`wifi_page: {enabled: false}`.

### API для своего сайта

Сайт устройства может рисовать настройки Wi-Fi в своём стиле (попап в углу), а работу оставить
библиотеке: подключите `/ap_portal/client.js` и вызывайте `window.apPortal` — `networks()`,
`scan()`, `connect(ssid, psk)` (вернёт адреса, где искать устройство после смены сети),
`watch(ssid, {host})` (дождётся устройства в новой сети и вернёт его адрес), `setApPassword()`,
`resetApPassword()`. Адреса и формат ответов — в [английском README](README.md#api-for-your-own-site).
Готовый попап для любой страницы: `<script src="/ap_portal/popup.js" data-accent="#3d7bff"></script>`
добавляет в угол кнопку Wi-Fi (Shadow DOM, стили сайта его не трогают). В штатную страницу ESPHome
с `local: true` свой скрипт не добавить — там `wifi_page: {ui_button: true}` отдаёт клиентам точки
доступа `/` как рамку вокруг страницы ESPHome с этой кнопкой поверх.
Ошибки приходят как `400` с `{"error": "<код>"}` (`ssid_empty`, `ssid_long`, `psk_length`,
`ap_password_length`), промис отклоняется с `Error.code`; `apPortal.check.ssid()/.psk()/.apPassword()`
проверяют то же самое до отправки.
По умолчанию API доступен только клиентам точки доступа; `api: {from_home: true}` открывает его и
домашней сети (под логином `web_server`, если он задан). Каждый POST должен нести заголовок `X-AP-Portal: 1` (`client.js` / `popup.js` шлют его сами) и, если браузер прислал `Origin`, идти с адреса самого устройства; иначе `403` `{"error":"forbidden"}` — чужая веб-страница не сменит роутер и пароль точки. Читать ответы ap_portal тоже могут только страницы самого устройства (`http://<IP точки>`, `http://<host>.local`, IP в сети роутера и предыдущий) — вместо `Access-Control-Allow-Origin: *` от ESPHome.

### Точка доступа не гаснет при подключении к роутеру

**ESPHome 2026.11 и новее — собственный режим ESPHome** (проверено на железе, без хаков):

```yaml
wifi:
  post_connect_roaming: false   # обязательно для always_on
  reboot_timeout: 15min         # 0s для устройства, которое живёт без роутера
  ap:
    ap_mode: always_on          # точка работает рядом с роутером
```

Точку поднимает и держит сам ESPHome; ap_portal её не трогает (сам не поднимает, `ap_timeout`
ESPHome не меняет) и добавляет всё остальное. Перезагрузку «без роутера» и здесь ведёт ap_portal
(см. ниже): своя у ESPHome перезагружала бы каждые `reboot_timeout` весь обрыв. `ap_mode: WISP`
запрещён (DNS ap_portal отнял бы у клиентов интернет); рядом с always_on запрещены
`keep_ap_on_connect` и `ap_raise: without_router`.

**ESPHome 2026.10 (или точка только на время без роутера):**


> [!CAUTION]
> **Экспериментально.** ESPHome выключает свою точку доступа каждый раз, когда подключается роутер
> (телефоны на ней отваливаются, Android перескакивает на другую сеть). `keep_ap_on_connect: true`
> убирает это: после старта Wi-Fi сбрасывает приватный флаг ESPHome `WiFiComponent::has_ap_`.
> Проверено только на ESPHome 2026.11.x — на других версиях сборка предупреждает; если ESPHome
> переименует поле, сборка упадёт (на устройстве ничего не сломается).

```yaml
ap_portal:
  keep_ap_on_connect: true
  reboot_timeout: 15min      # по умолчанию: wifi: reboot_timeout; 0s = никогда
  ap_raise: always           # или without_router: точка только без роутера
                             # (раньше ap_mode: always / fallback — читается, с предупреждением)
  fallback:
    after: 30s               # столько без роутера — точка включается
    off_when_idle: 60s       # роутер вернулся и на точке никого столько — точка выключается
```

Перезагрузка ESPHome «без роутера» либо не видит точку, которую поднял ap_portal, либо (с `wifi: ap:
ap_mode: always_on`) перезагружает снова и снова весь обрыв, поэтому её во всех режимах берёт на себя ap_portal: через `reboot_timeout`
(по умолчанию `wifi: reboot_timeout`, 15 мин) без роутера и когда на точке **никого** нет. Клиент на
точке останавливает таймер; отсчёт начинается заново, когда ушёл последний клиент или вернулся
роутер. Таймер ещё ждёт, пока идёт смена роутера или откат, идёт OTA и минуту после последнего запроса
страницы клиентом точки. Работает он, только если роутер был виден с момента загрузки, задана
непустая сеть роутера (в YAML или сохранена со страницы) и Wi-Fi включён: устройство без роутера
(или с неверной сетью со страницы) из-за этого не перезагружается, а долгое отключение роутера стоит
одной перезагрузки, а не одной каждые 15 мин. `0s` — выключить. Такому устройству нужен и
`api: reboot_timeout: 0s` (иначе ESPHome перезагружает его через 15 мин без Home Assistant; сборка
предупредит).

Первое подключение к роутеру после старта всё равно может перенести точку на канал роутера
(радио одно) — клиент на ней отвалится на секунду.

### Забыли пароль точки доступа

С `password_persist: true` пароль, заданный со страницы, переживает и перезагрузку, и перепрошивку,
поэтому есть путь назад без сети:

- нажмите **RESET** на плате 4 раза, после каждого нажатия ждите 2–3 с (каждый запуск должен быть
  короче 10 с) — на 4-м запуске точка поднимется с паролем из `wifi: ap:`;
- или удерживайте **BOOT** 5 с, пока устройство работает.

Каждый быстрый запуск засчитывает и `safe_mode` ESPHome (10 запусков короче 60 с), поэтому между
двумя сериями дайте устройству поработать минуту. Считаются только включение питания и кнопка RESET:
пробуждения из глубокого сна, OTA, программные перезагрузки, сбои и просадки питания — никогда.
Если пин BOOT в вашей конфигурации занят чем-то другим, удержание BOOT отключается (сборка об этом
предупредит); укажите свою кнопку в `pin:`.

### Шаблоны стартовой страницы

Встроенная страница и ваш `html` проходят через один небольшой шаблонизатор:

| Синтаксис | Что делает |
|---|---|
| `{{name}}` | переменная, с экранированием HTML |
| `{{{name}}}` | переменная как есть (SVG, готовый фрагмент) |
| `{{#if name}}…{{else}}…{{/if}}` | показывается, если переменная не пустая, не `0` и не `false`; можно вкладывать |
| `{{#unless name}}…{{/unless}}` | наоборот |

Встроенные переменные: `title`, `ap_ip`, `sta_ip` (пусто без роутера), `host` (для
`http://{{host}}.local/`), `ssid`, `enter` (`/`, страница устройства), `landing`,
`mode`, `clients`, а также ключи оформления выше (`accent_color`, `accent_text`, `icon_svg`,
`primary_label`, `secondary_label`, `secondary_href`). Лямбды из `vars:` выполняются в главном
цикле раз в секунду, никогда в задаче веб-сервера. Страница без `{{` отдаётся сжатой gzip прямо из
флеша.

```html
<h1>{{title}}</h1>
<p>Батарея {{battery}} %</p>
{{#if sta_ip}}<a href="http://{{sta_ip}}/">Домашняя сеть</a>{{/if}}
<a href="{{enter}}">Открыть панель</a>
```

Пока работает `captive_portal` (щадящий режим без роутера), каждый GET со стороны точки доступа
проходит через `ap_portal`: страницы устройства работают как обычно, форма Wi-Fi ESPHome не
показывается никогда.

## Проверки при сборке

| Ситуация | Результат |
|---|---|
| Нет `wifi: ap:` | ошибка |
| Нет `manual_ip` в `wifi: ap:` или адрес из частного диапазона | предупреждение: Android не покажет окно входа |
| SSID вместе с хвостом MAC длиннее 32 байт | ошибка |
| `password_reset: power_cycles` не меньше `safe_mode: num_attempts` | ошибка |
| Пин BOOT для `password_reset` занят другим компонентом | предупреждение, удержание BOOT выключено |
| Имя в `vars:` не вида `[a-z_][a-z0-9_]*` или совпадает со встроенной переменной | ошибка |
| `mode: page` / `mode: gate`, `enter_path`, `enter_window`, `pass_paths`, `on_enter` (удалены в 0.2.0) | ошибка |
| ESPHome не 2026.11.x | предупреждение |
