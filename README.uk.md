# ap_portal для ESPHome

[English](README.md) · **Українська** · [Русский](README.ru.md)

> **Статус: 0.x.** Точка доступу, щадний режим, стартова сторінка, пошук мереж і пароль
> працюють і перевірені на ESP32-S3; далі — перенесення на бібліотеку перших реальних пристроїв.
> До випуску з тегом закріплюйте конкретний коміт, якщо від пристрою щось залежить.

ESP32 тримає **власну точку доступу Wi-Fi одночасно з підключенням до роутера**. Телефон,
що підключився до неї, отримує вікно **«Увійти в мережу»** і потрапляє на сторінку пристрою — є
роутер чи ні.

Чого не вміє штатний `captive_portal` ESPHome, а вміє `ap_portal`:

- точка доступу лишається увімкненою після підключення до роутера;
- власна стартова сторінка: перенаправлення, сторінка або **«вхідні двері»** (gate: панель
  відкривається лише після натискання кнопки);
- запити з домашньої мережі не чіпаються — стартову сторінку бачать лише клієнти точки доступу;
- **щадний режим**: без роутера ESPHome сканує всі канали й перезапускає адаптер, телефони на
  точці втрачають пакети або відпадають (вимір: 45 % втрат). `ap_portal` тримає радіо на каналі
  точки (вимір: менше 2 % втрат разом із поверненням роутера) і все одно знаходить роутер, коли той
  з'явиться, навіть на іншому каналі;
- до SSID можна додати хвіст MAC, пароль змінюється з самого пристрою і переживає перезавантаження.

Працює на будь-якому ESP32 із фреймворком ESP-IDF (перевірено на ESP32-C3 та ESP32-S3).
Перевірено з **ESPHome 2026.11.x**; на інших версіях збірка видає попередження.

## Швидкий старт

```yaml
wifi:
  ssid: my-router
  password: router-password
  ap:
    ssid: My-Device
    password: device1234
    manual_ip:                  # 100.64.4.1: Android показує вікно входу (на приватну адресу — ні)
      static_ip: 100.64.4.1
      gateway: 100.64.4.1
      subnet: 255.255.255.0

web_server:
  version: 3
  local: true                   # сторінка працює без інтернету

external_components:
  - source: github://daimonkor/esphome-ap-portal@main   # тег після виходу v0.1.0
    components: [ap_portal]

ap_portal:
```

SSID, пароль і адреса беруться з `wifi: ap:` і в `ap_portal` не дублюються.

## Налаштування

```yaml
ap_portal:
  id: portal
  active: true                  # true / false / !lambda — коли працюють точка, DNS і сторінка
  ssid_suffix_mac: false        # MyDevice -> MyDevice-4FD30C
  password_persist: false       # зберігати пароль з ap_portal.set_password після перезавантаження
  log_exclude_prefixes: []      # шляхи, які не пишуться в лог VERBOSE, наприклад [/sd/]
  dns:
    enabled: true
  landing:
    mode: redirect              # redirect (302) / page (200) / gate
    path: /welcome
    # змінні вбудованої сторінки (доступні й у власному html):
    title: My Device            # за замовчуванням friendly_name
    accent_color: "#3d7bff"     # текст на кнопці білий або чорний — за контрастом
    icon_svg: {file: icon.svg}  # або рядком "<svg ...>"
    primary_label: Open device page
    secondary: {label: Router Wi-Fi, href: "/#wifi"}
    # власна сторінка замість вбудованої (шаблон, див. нижче):
    # html: {file: landing.html}
    # vars:                     # власні змінні шаблону
    #   battery: !lambda return to_string((int) id(soc).state);
    #   fw: "1.2.3"
    # лише для gate:
    # enter_path: /enter        # кнопка: видає прохід цьому клієнту і робить 302 на /
    # enter_window: 30min       # прохід спливає після стількох хвилин без запитів
    # pass_paths: [/history.bin]  # ніколи не перехоплюються
  api:                          # адреси /ap_portal/ і client.js для власного сайту
    enabled: true
    from_home: false            # і з домашньої мережі (під логіном web_server)
  router_fallback:              # мережа зі сторінки не підключається після перезавантаження:
    timeout: 45s                # чекати стільки, потім по черзі кроки нижче
    previous: true              # повернутися до мережі, на якій пристрій був до цього
    firmware: true              # потім до мережі з YAML (wifi: ssid / networks)
    # firmware: {ssid: Backup-Net, password: !secret backup}   # або власна запасна мережа
  on_router_fallback:           # to: "previous" / "firmware" / "none", ssid
  wifi_page:                    # вбудована сторінка /wifi, лише для клієнтів точки (у gate — теж без кнопки)
    enabled: true               # список мереж, підключення до роутера, пароль точки доступу
    path: /wifi                 # сюди веде друга кнопка стартової сторінки, якщо не задано `secondary`
    ap_password: true           # блок пароля точки доступу
  password_reset:               # з password_persist: повернути пароль з wifi: ap:
    power_cycles: 4             # кнопка RESET (або живлення) 4 рази поспіль, кожен запуск коротший за 10 с; 0 = вимк
    # pin: GPIO2                # кнопка, яку тримають під час роботи; за замовчуванням BOOT на платі
    hold: 5s                    # (GPIO0 на ESP32/S2/S3, GPIO9 на C3/C6, GPIO28 на C5); pin: false = вимк
                                # своя кнопка на GND: pin: {number: GPIO2, mode: {input: true, pullup: true}, inverted: true}
  on_client_connected:          # mac (std::string)
  on_client_disconnected:       # mac
  on_ap_restored:               # ESPHome вимкнув точку, ap_portal підняв її знову
  on_portal_start:
  on_portal_stop:
  on_landing:                   # ip, path — показано стартову сторінку
  on_enter:                     # mac, ip — gate: клієнт натиснув кнопку
  on_power_cycle:               # count — швидкий запуск у серії (блимнути світлодіодом)
  on_password_reset:            # source: "power_cycles" або "button"
```

Дії: `ap_portal.scan` (фоновий пошук мереж без розриву зв'язку з роутером),
`ap_portal.set_password` (`password:` порожній — відкрита мережа, або 8..63 символи; застосовується
через 2 с, щоб сторінка, яка попросила, встигла отримати відповідь; з `password_persist: true`
переживає перезавантаження), `ap_portal.reset_password` (повернути пароль з `wifi: ap:`, збережений
стирається).

З лямбд: `id(portal).is_active()`, `client_count()`, `ap_ip()`, `ssid()`, `is_scanning()`,
`has_custom_password()`.

### Сторінка Wi-Fi

`/wifi` показує мережі навколо (фоновий пошук, поки роутер підключений), підключає пристрій до
мережі роутера (зберігає ESPHome, переживає перезавантаження) і змінює пароль точки доступу. Її
бачать лише клієнти точки доступу — ніколи домашня мережа; у режимі gate — і до кнопки (захист —
пароль точки). Кнопка Wi-Fi на стартовій сторінці відкриває її попапом на місці.
Її адреси — під `/ap_portal/`. Якщо у пристрою власна сторінка налаштувань Wi-Fi, вимкніть:
`wifi_page: {enabled: false}`.

### API для власного сайту

Сайт пристрою може малювати налаштування Wi-Fi у своєму стилі (попап у куті), а роботу залишити
бібліотеці: підключіть `/ap_portal/client.js` і викликайте `window.apPortal` — `networks()`,
`scan()`, `connect(ssid, psk)` (поверне адреси, де шукати пристрій після зміни мережі),
`watch(ssid, {host})` (дочекається пристрою в новій мережі й поверне його адресу), `setApPassword()`,
`resetApPassword()`. Адреси та формат відповідей — в [англійському README](README.md#api-for-your-own-site).
Готовий попап для будь-якої сторінки: `<script src="/ap_portal/popup.js" data-accent="#3d7bff"></script>`
додає в кут кнопку Wi-Fi (Shadow DOM, стилі сайту його не чіпають). У штатну сторінку ESPHome з
`local: true` власний скрипт не додати — там `wifi_page: {ui_button: true}` віддає клієнтам точки
доступу `/` як рамку навколо сторінки ESPHome з цією кнопкою поверх.
Помилки приходять як `400` з `{"error": "<код>"}` (`ssid_empty`, `ssid_long`, `psk_length`,
`ap_password_length`), проміс відхиляється з `Error.code`; `apPortal.check.ssid()/.psk()/.apPassword()`
перевіряють те саме до надсилання.
За замовчуванням API доступний лише клієнтам точки доступу; `api: {from_home: true}` відкриває його
й домашній мережі (під логіном `web_server`, якщо його задано).

### Точка доступу не гасне при підключенні до роутера

**ESPHome 2026.11 і новіше — власний режим ESPHome** (перевірено на залізі, без хаків):

```yaml
wifi:
  post_connect_roaming: false   # обов'язково для always_on
  reboot_timeout: 15min         # 0s для пристрою, що живе без роутера
  ap:
    ap_mode: always_on          # точка працює поруч із роутером
```

Точку піднімає й тримає сам ESPHome; ap_portal її не чіпає (сам не піднімає, `ap_timeout` ESPHome
не змінює) і додає все інше. Без роутера ESPHome перезавантажується через `reboot_timeout`, лише
поки на точці нікого немає. `ap_mode: WISP` заборонено (DNS ap_portal відібрав би в клієнтів
інтернет); поруч з always_on заборонені `keep_ap_on_connect`, `ap_mode: fallback` і
`reboot_timeout` самого ap_portal.

**ESPHome 2026.10 (або точка лише на час без роутера):**


> [!CAUTION]
> **Експериментально.** ESPHome вимикає свою точку доступу щоразу, коли підключається роутер
> (телефони на ній відпадають, Android перескакує на іншу мережу). `keep_ap_on_connect: true`
> прибирає це: після старту Wi-Fi скидає приватний прапорець ESPHome `WiFiComponent::has_ap_`.
> Перевірено лише на ESPHome 2026.11.x — на інших версіях збірка попереджає; якщо ESPHome
> перейменує поле, збірка впаде (на пристрої нічого не зламається).

```yaml
ap_portal:
  keep_ap_on_connect: true
  reboot_timeout: 15min      # типово: wifi: reboot_timeout; 0s = ніколи
  ap_mode: always            # або fallback: точка лише без роутера
  fallback:
    after: 30s               # стільки без роутера — точка вмикається
    off_when_idle: 60s       # роутер повернувся і на точці нікого стільки — точка вимикається
```

Коли точку піднімає сам ap_portal (усе, крім `wifi: ap: ap_mode: always_on`), перезавантаження
ESPHome «без роутера» цієї точки не бачить, тож його бере на себе ap_portal: через `reboot_timeout`
(типово `wifi: reboot_timeout`, 15 хв) без роутера і коли на точці **нікого** немає. Клієнт на точці
зупиняє таймер; відлік починається знову, коли пішов останній клієнт або повернувся роутер.
Пристрою, що живе без роутера, — `wifi: reboot_timeout: 0s`.

Перше підключення до роутера після старту все одно може перенести точку на канал роутера
(радіо одне) — клієнт на ній відпаде на секунду.

### Забули пароль точки доступу

З `password_persist: true` пароль, заданий зі сторінки, переживає і перезавантаження, і
перепрошивку, тому є шлях назад без мережі:

- натисніть **RESET** на платі 4 рази, після кожного натискання чекайте 2–3 с (кожен запуск має
  бути коротшим за 10 с) — на 4-му запуску точка підніметься з паролем з `wifi: ap:`;
- або утримуйте **BOOT** 5 с, поки пристрій працює.

Кожен швидкий запуск зараховує й `safe_mode` ESPHome (10 запусків коротших за 60 с), тому між
двома серіями дайте пристрою попрацювати хвилину. Рахуються лише ввімкнення живлення і кнопка RESET:
пробудження з глибокого сну, OTA, програмні перезавантаження, збої та просідання живлення — ніколи.
Якщо пін BOOT у вашій конфігурації зайнятий чимось іншим, утримання BOOT вимикається (збірка про це
попередить); вкажіть власну кнопку в `pin:`.

### Шаблони стартової сторінки

Вбудована сторінка і ваш `html` проходять через один невеликий шаблонізатор:

| Синтаксис | Що робить |
|---|---|
| `{{name}}` | змінна, з екрануванням HTML |
| `{{{name}}}` | змінна як є (SVG, готовий фрагмент) |
| `{{#if name}}…{{else}}…{{/if}}` | показується, якщо змінна не порожня, не `0` і не `false`; можна вкладати |
| `{{#unless name}}…{{/unless}}` | навпаки |

Вбудовані змінні: `title`, `ap_ip`, `sta_ip` (порожньо без роутера), `host` (для
`http://{{host}}.local/`), `ssid`, `enter` (`enter_path` у режимі gate, інакше `/`), `landing`,
`mode`, `clients`, а також ключі оформлення вище (`accent_color`, `accent_text`, `icon_svg`,
`primary_label`, `secondary_label`, `secondary_href`). Лямбди з `vars:` виконуються в головному
циклі раз на секунду, ніколи в задачі веб-сервера. Сторінка без `{{` віддається стиснутою gzip
просто з флешу.

```html
<h1>{{title}}</h1>
<p>Батарея {{battery}} %</p>
{{#if sta_ip}}<a href="http://{{sta_ip}}/">Домашня мережа</a>{{/if}}
<a href="{{enter}}">Відкрити панель</a>
```

Поки працює `captive_portal` (щадний режим без роутера), кожен GET з боку точки доступу проходить
через `ap_portal`: сторінки пристрою працюють як завжди, форма Wi-Fi ESPHome не показується ніколи.

## Перевірки під час збірки

| Ситуація | Результат |
|---|---|
| Фреймворк не ESP-IDF | помилка |
| Немає `wifi: ap:` | помилка |
| Немає `manual_ip` у `wifi: ap:` або адреса з приватного діапазону | попередження: Android не покаже вікно входу |
| SSID разом із хвостом MAC довший за 32 байти | помилка |
| `password_reset: power_cycles` не менше за `safe_mode: num_attempts` | помилка |
| Пін BOOT для `password_reset` зайнятий іншим компонентом | попередження, утримання BOOT вимкнено |
| Ім'я у `vars:` не виду `[a-z_][a-z0-9_]*` або збігається з вбудованою змінною | помилка |
| `enter_path`, `enter_window`, `pass_paths` без `mode: gate` | помилка |
| ESPHome не 2026.11.x | попередження |
